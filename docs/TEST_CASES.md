# Test cases

The suite you will build: 111 cases in 16 specs, ported from the playwright-pom suite so you can compare the two patterns case by case. Every case is already a `test.fixme` placeholder in its spec file, with its ID at the start of the title, so `npm run test:list` doubles as your to-do list.

## How to read this

- **ID**: `<AREA>-<LAYER>-<NN>`. Use it in the test title, in commits and in ROADMAP checkboxes.
- **Scenario**: Given / When / Then in the actor's voice. The actors are:
  - **Alice**: the account owner. She has the api key and the session from the setup project.
  - **Mallory**: an intruder with a missing or wrong api key or password (401 and login-failure tests).
  - **Guest**: a visitor with no session at all (redirect and empty-form tests).
- **Cases**: a parameterised scenario. Put the values in a table at the top of the spec and loop over it, one `test()` per row; keep the ID and add the value to the title.
- **PRODUCT DEFECT** (11 cases): the app is known to be wrong here. Write the correct assertion, then leave the test as `test.fixme` with the defect annotation, as the POM suite does.
- **POM**: the line of the equivalent test in `../playwright-pom/tests/`. Read it _after_ you have written your version.
- **Tags**: `@stateful` cases use the account-wide basket and run on one worker, and `@login` cases spend a rate-limited login. `@smoke` is the fast confidence set.
- **Done**: tick the box (`⬜` → `✅`) when the case is implemented and green, or parked on a defect.
